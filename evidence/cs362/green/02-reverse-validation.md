# cs#362 反向验证

在修复之上逐个注入变异，`dotnet build --no-incremental` 后只跑 `CancelledDemandLoadCommandTests`。脚本 `02-reverse-validation-mutations.py`：
源码先备份，替换匹配数不为 1 就不跑，构建失败就不跑测试并记下编译错误，跑完按备份还原，记下测试进程的退出码。原始输出
`02-reverse-validation-raw.txt`（四轮，见文末）。变异用 `runtime.AgvId.Length < 0` 顶替条件：`if (false)` 触发不可达代码告警
（按错误处理），`entered is null` 触发空值分析，两种都编译不过、什么都没测。

复核有四条：旅程仍在等录入（「阶段」）、需求仍是 `Accepted`（「需求」）、归属仍是游标读到的那个（「归属」）、本站没有开着的扫码前取消（「取消」）。
入站能插进这个窗口的写法有三种：

| 写法 | 写了什么 | 挡得住它的复核 |
| --- | --- | --- |
| 乙自己的终结（扫码前取消 ALL_EMPTY → `PickupStopTermination`） | 需求 `Cancelled`、归属 `TERMINATED`，阶段不动 | 需求、归属 |
| 乙的取消结果证明不了空（`KeepDemandAndJourneyBlockedAsync`） | 需求 `RecoveryRequired`、旅程 `Blocked`，归属不动 | 需求、阶段 |
| 同站丙的扫码前取消在锁外查取消之后被授权 | 乙的需求、归属、阶段都不动 | 只有取消 |

## 第四轮（审查之后，最终）结果，7 条用例

注入之前写下的预期：R1 全红，四格各红在自己的后果上；R5 只红「丙的取消」那一条；R2、R3、R4 单独存活；R23 红终结那五条；R24 红证明不了空那一条。

| 变异 | 去掉的复核 | 结果 | 退出码 |
| --- | --- | --- | --- |
| R1 | 整个复核 | 7/7 红 | 1 |
| R2 | 需求 | 全绿（存活） | 0 |
| R3 | 归属 | 全绿（存活） | 0 |
| R4 | 阶段 | 全绿（存活） | 0 |
| R5 | 取消 | 只红「丙的取消」那一条 | 1 |
| R23 | 需求 + 归属 | 终结那五条红，其余两条绿 | 1 |
| R24 | 需求 + 阶段 | 只红「证明不了空」那一条 | 1 |

**各条的护栏，照实写：**「取消」一条单删就红（R5）。「需求」一条单独就挡得住前两种写法。「归属」「阶段」两条**只在组合层面有护栏**：
单删不红，与「需求」一起删才红（R23、R24）。它们留着，是为了不把正确性押在「终结与转阻塞总是连带写需求」上；今天这个前提成立，
所以它们今天没有单独的判别用例，也构造不出来。

R1 下每一条红在哪（读到的）：

| 用例 | 红在 |
| --- | --- |
| 装上了 | 乙归属 `LOADED`、装货 `Committed`、旅程 `Completed`、完成记录只有甲——**货留在车上**，乙记着 `Cancelled` |
| 期限前报空 | 乙需求 `RecoveryRequired`（从 `Cancelled` 被改写）、装货 `RecoveryRequired`、旅程 `Blocked` |
| 期限后报空 | 乙归属 `LOADING`、装货 `Failed`、旅程停在 `AwaitingLoadResult` |
| 装货中按取消 | 乙归属 `LOADING`、装货 `Prepared`、旅程停在 `AwaitingLoadResult`（在途取消被拒） |
| 本站还有丙 | 「已取消的乙被下了装货命令」 |
| 取消证明不了空 | 「证明不了空的取消之后，乙仍被下了装货命令」 |
| 丙的取消开着 | 「丙的取消开着时，乙被下了装货命令」 |

每条用例末尾有前提断言：引擎在复核那一步让开了恰好一次、让的是乙（事件 2190，`LogLoadYieldedToEndedDemand`）。放在末尾，是为了去掉修复时
每一格先红在自己的后果上（上表）；它防的是触发点哪天前移到引擎认定录入之前，「没下命令」因为引擎读到了新状态而恒真。

## 四轮的来由

1. 第一轮：「本站还有丙」红在一句写成「前提」的归属断言上——那句断言本身会被缺陷改写，不是真前提。
2. 第二轮：前提改成「这一刻还没有人答这条录入」，它红在「下了装货命令」上。
3. 第三轮：排查终结写法时发现「证明不了空」只写需求，补用例，加 R4、R24。
4. 第四轮（审查）：补「丙的取消」用例与 R5；三条交错用例补让开一次的前提断言；脚本改为构建失败不跑、记退出码。「丙的取消」第一版挂在
   与另外几条相同的触发点上，前提断言红在「引擎没有让开」——取消是「开」而不是「结」，那一刻落下会被锁外那次查取消先挡掉、走不到写锁里的
   复核；触发点改挂在复核录入时读花篮容量表的那条查询上（锁外查取消之后、进写锁之前）。
