## 为什么（读到的与推的分开）

读到的：

- 车载端在**使用**证据时按当时时刻判时效：onboard-hmi `w2g/fp-v2-impl` 的 `App.xaml.cs:79-83`，`IsStoppedAndFresh(DateTimeOffset.UtcNow, 5000ms, …)`。沿用来的证据要撑到下一次拉取返回。
- 装置上 vehicle-safety 应答耗时（服务端日志）：38069023213 p50 272 ms、p90 776 ms、最大 2271 ms；38071111799 p50 428 ms、p90 860 ms、最大 1179 ms；38071136418-03 p50 223 ms、p90 603 ms、最大 1079 ms。现场同一读法约 70～110 ms。
- 38069023213 那一次闪：一次沿用的请求耗时 2270.9 ms 才返回，下一次 583.3 ms，车载端 00:50:01.90 收到 `RECOVERY_REQUIRED`、00:50:02.14 回 `READY`。

推的：

- 沿用要成立，需要「上一次读全的开始时刻到这次应答返回 ≤ 窗口」（上一次读全一般是前一次拉取，约 1 秒前），又需要「窗口 + 请求耗时 + 拉取间隔 1 秒 + 下一次请求耗时 ≤ 5 秒」。请求耗时到 0.6 秒以上，两者没有交集。
- 3 秒那一版撞上的是后一条（证据过期），1.5 秒那一版撞上的是前一条（沿用不了，回未知）。
