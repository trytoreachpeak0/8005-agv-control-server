# agv02／agv03 今天的系统时间变更（只读，2026-10-11 20:25）

起因：ws#16、ws#20 两次看到车上计划任务回报的 lastRunTime 与真实时刻对不上（12:38 比脚本结束晚 12 秒、20:04 比预检早 20 秒），审查怀疑 agv02 系统时钟跳变。只读查了 `Microsoft-Windows-Kernel-General` Id 1 与 `w32tm /query /status /verbose`，没改任何配置。原始输出：`agv02-clock.txt`、`agv03-clock.txt`（w32tm 段是 GBK 中文）。

| 车 | 今天的系统时间变更 | w32tm |
| --- | --- | --- |
| agv02 | **两次，都在 10:25:56**：+1.423 s、+0.002 s（svchost，reason 1）。12:38、20:04 前后**没有任何变更** | 源 172.19.205.222，状态「同步」，相位偏移 0.0118 s，上次成功同步 19:25:55，轮询 4096 s |
| agv03 | 两次：09:26:37 从 2027-02-08T13:03:14Z 调回 2026-10-11T01:26:37Z（约 −120 天，镜像车主板时钟快的已知现象，开机校时纠正），随后 +0.005 s | 源 172.19.205.222，状态「同步」，相位偏移 0.0310 s，上次成功同步 18:32:46 |

两车「上次同步错误: 2（只有陈旧的时间数据，没有重新同步）」，指最近一轮没取到新数据，偏移本身很小。

结论：**12:38、20:04 两次对不上不是 agv02 系统时钟跳变造成的**（读到的）。差异更可能来自计划任务 LastRunTime 本身的含义（推测，未验证）。
