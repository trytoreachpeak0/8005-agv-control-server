# cs#234 车载端静默失联：L2 证据三份

| 目录 | 结论 | 注入了什么 | 红在哪里 |
| --- | --- | --- | --- |
| `20260920-cs234-red-session-layer` | FAIL | 会话层的读取不再设窗口（`idle.CancelAfter(Timeout.InfiniteTimeSpan)`） | `L2-SL-02`：假车载端的 readiness 一直停在 `READY`，服务端不关这条静默的连接 |
| `20260920-cs234-red-journey-block` | FAIL | 引擎不再判失联（`NameSilentOnboardSessionAsync` 的调用短路掉） | `L2-SL-02` 绿（连接确实被关了），`L2-SL-04` 红：阻断端点始终不列这条旅程 |
| `20260920-cs234-pass-after-review` | PASS | 无 | 十一条判据全过，跑在独立审查的修改之后 |

**分两次注入，是为了让红点指得到具体一端。** 一次全拿掉，两端的缺失会混在同一个超时里，看不出是谁没做。
现在第一份说「服务端不关连接」，第二份说「连接关了但看板上还是什么都没有」——正是这张票要补的两格。

两次注入都用文件备份还原，还原后 `git hash-object` 与 `git rev-parse HEAD:<path>` 逐字节一致，
证明注入既不多也不少。

**两份红目录各带一个 `INJECTION.md`。** 不带的话，`SUMMARY.md` 里的 `controlServerCommit` 与绿证据那份
一模一样——编排器记的是工作树所在的提交，看不见工作树上未提交的注入——于是一份红证据在宣称自己跑的是
干净提交。独立审查提的（S3）。

`20260920-cs234-red-journey-block/logs/control-server.out.log` 里有 60 条
`System.IO.IOException: No recovered Onboard peer is connected`，每秒一条。那是这张票开工时没料到、
第一次实跑才看见的事：连接一没，`ReplayPendingForSessionAsync` 就抛，整轮 fail-closed，到站那些分支
根本走不到。判定因此放在推进之前，而不是放进「到站不可信」之后。
