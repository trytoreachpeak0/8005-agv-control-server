# `.GetNewClosure()` 到底捕获什么：二十种形状的实测

> **这个目录是 cs#266 那条守卫的唯一依据。** 守卫要判「哪些写法会静默捕获到空」，而这件事**不能靠读文档
> 或读代码推**——下面二十种形状里有四种的结果与直觉相反，其中两种推翻了 cs#203 写下的结论。

## 结论：规则不是「嵌套」

cs#203 实测了**一种**嵌套形状发现它捕获空作用域，写下的规则是「`.GetNewClosure()` 嵌在一个已经是闭包的
scriptblock 内部时，捕获到空作用域」。**那是过度概括**：

- **嵌套但捕获自己作用域变量的，完全正常**（形状 3、7、14）；
- **不嵌套的反而是空的**——普通 scriptblock 里（形状 4）、函数内定义的函数里（形状 6）。

**「嵌套」既不充分也不必要。** 拟合全部数据的规则是：

> **`GetNewClosure()` 对「调用那一刻、无限定名查得到」的变量做按值快照。**

## 合法写法（守卫必须放过）

| # | 写法 | 出处 |
| --- | --- | --- |
| 1 | 函数体顶层捕获本函数的局部或参数 | `result-shapes.txt` 形状 1、10 |
| 2 | 嵌套，但只捕获闭包自己体内定义的变量或自己的参数 | 形状 3、7 |
| 3 | **嵌套，但先把外层变量复制到本地再捕获**（推荐解法） | 形状 14、`result-module-scope.txt` T4 |
| 4 | `ForEach-Object` 块内取闭包（那个块跑在调用者作用域里） | 形状 5 |
| 5 | **脚本（`.ps1`）顶层变量**，含点源进来的顶层变量，在同一作用域捕获 | 形状 11、`result-cross-file.txt` 2 |
| 6 | 带参调用的脚本，其**参数**在顶层被捕获 | `result-cross-file.txt` 1 |

第 6 条是场景文件的常态：`Invoke-L2Scenario.ps1` 用 `& $scenarioPath -Context $context` 调用场景，
**不是点源**。

## 非法写法（守卫该报）

| 写法 | 出处 |
| --- | --- |
| 捕获**外层函数**作用域的变量（从更深作用域取闭包时），不论那个更深作用域是闭包、普通 scriptblock 还是嵌套函数 | 形状 2、4、6、8 |
| 捕获**调用方**的变量（点源函数里取闭包时） | `result-cross-file.txt` 4 |
| **模块（`.psm1`）顶层变量**被同模块闭包捕获 | `result-module-scope.txt` T1 |
| **`$script:` / `$global:` 限定读**——无条件，与嵌套和文件类型都无关 | 形状 13、T5、`result-cross-file` |
| 变量在取闭包**之后**才赋值 | 形状 12（符合直觉，列出以求完整） |

## 两条与直觉最不一样的，都带对照组

**一、`$script:` 限定读被 `GetNewClosure` 这个动作本身破坏。**

```
T5 $script: 限定 + 取闭包        : EMPTY
T6 $script: 限定不取闭包（对照） : MOD-TOP
T3 直接读（对照，证明变量存在）  : MOD-TOP
```

**同样的读，不取闭包时正常。** 所以这不是写法问题，是取闭包把它破坏了——**而无限定名读同一个脚本级变量
反而是正常的**（形状 11），因为那是按值快照，而限定读是运行时查找，那时闭包的脚本作用域已经不是原来那个。

**二、模块顶层变量在同模块的闭包里读不到。**

```
T1 模块顶层变量 + 取闭包        : EMPTY
T2 同上但不取闭包（对照）       : MOD-TOP
T4 先复制到本地再取闭包         : MOD-TOP
```

**这一条决定守卫的形状**：`.ps1` 的文件顶层名字算可见，**`.psm1` 的不算**。一套规则扫全部会在模块里漏报。

**今天 0 个活实例**：八个模块有顶层变量（都写成 `$script:` 限定），而那些文件里一个闭包站点都没有。
**所以这条守卫是预防，不是在修一个现存缺陷**——别把它读成「我们刚修好了什么」。

## 这份清单的边界，明写

**它是「作者想到的二十种形状」，不是全集。** 没有覆盖的至少有：`Set-Variable` / `New-Variable` 建的变量、
间接变量名、`Invoke-Expression`、`$using:`、以及远程会话。**守卫对这些一律按「不确定 → 当作可见 → 不报」
处理**，宁可漏报也不要误报——**一次误报会挡住一张与它无关的票，而被挡的人没有能力自己判断该不该被挡**，
因为真正的机理要跑完这二十种形状才说得清。
